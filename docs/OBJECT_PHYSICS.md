# 未知の物理特性（質量・摩擦）に対するGraspの評価と残差SAC学習

物体の質量・摩擦をポリシーに与えずに、Graspを学習で頑健化できるかを検証した記録。
数値はすべて記載したコマンドの実行出力から書いている。生成物（`runs/`）はgit管理外。

## 1. 物体物理のDomain Randomization（第1段階）

実装: `crates/mujoco-runtime/src/pick_place.rs`（`ObjectRandomization` / `ObjectPhysics`）、
`model_access.c`（`robot_sim_read_object` / `robot_sim_write_object`）、Python `PickPlaceSimulator.set_object_randomization(mass=, friction=)` / `object_physics()`。

- reset時にだけ適用し，エピソード途中では変更しない．`PickPlaceSim::reset`はモデルを書き換えてから`Simulator::reset_seed`でmjDataを作り直す．
- seedごとに決まる独立した乱数系列を使う．DRを有効にしても同じseedで立方体と目標の位置は変わらない（テストで確認）．関節DR（`Simulator::configure_randomization`）とは独立に切り替えられる．
- 質量を変えると主慣性モーメントも同じ比率でスケールする（同形状の箱は I = m a²/6）．書き換え後に`mj_setConst`を呼び，`body_subtreemass`・`invweight0`・`stat.meaninertia`などの質量に依存する定数を再計算する．トポロジや配列サイズは変えない．
- **摩擦の落とし穴（実測で判明）**: SO-101のジョー衝突geomは`priority="1"`（摩擦1.0・condim 6・solref 0.01）である．MuJoCoでは優先度が高いgeomの接触パラメータが使われるため，**既存シーンの立方体の摩擦1.2はジョーとの接触に一切効いていなかった**（テーブルとの接触だけ max(1.2, 1.0) = 1.2）．
  そこで摩擦DRを有効にしたときだけ立方体geomの優先度を「全geomの最大値+1」（=2）にし，立方体の摩擦・condim 4・solref 0.01がジョーとテーブルの両方の接触を決めるようにした．質量だけのDRや，DRを無効にした状態ではモデルを一切変更しない．
- ground truthは`object_physics()`でログ用に取得できる．`state()`には含めない（テストで確認）．

### 実効接触パラメータ（`mjData.contact`の実測）と実験上の制約

`cargo run --release -p mujoco-runtime --example contact_probe > runs/object-physics/contact_parameters.jsonl`
（seed 3,000,000，静止時とIK Grasp中に現れた接触の値．solimpはすべて (0.9, 0.95, 0.001, 0.5, 2)）

| 設定 | ジョー接触 dim / friction[5] / solref | テーブル接触 dim / friction[5] / solref |
|---|---|---|
| DR無効 | 6 / (1.0, 1.0, 0.005, 5e-4, 5e-4) / 0.01（ジョーの値） | 4 / (1.2, 1.2, 0.005, 1e-4, 1e-4) / **0.015**（混合） |
| 質量のみDR（0.05 kg） | DR無効と同じ | DR無効と同じ |
| 摩擦DR μ=1.2（priority 2） | **4** / (1.2, 1.2, 0.005, 1e-4, 1e-4) / 0.01 | 4 / (1.2, …) / **0.01** |
| 摩擦DR μ=0.1（priority 2） | **4** / (0.1, 0.1, 0.005, 1e-4, 1e-4) / 0.01 | 4 / (0.1, …) / **0.01** |

制約（今回は修正せず，記録して結果の解釈に含める）:
1. 摩擦DRのμは，ジョー接触とテーブル接触の両方の滑り摩擦（接線2方向）を同時に変える．μ ≤ 0.1でPlace後に滑る失敗（§2）はこのためで，Graspの能力とは別の問題である．
2. priority変更によって，摩擦以外の値も変わる．ジョー接触はcondim 6→4になり（転がり摩擦がなくなる．ねじり摩擦0.005は残る），テーブル接触のsolrefは0.015→0.01（やや硬い）になる．そのため**摩擦DR有効時のμ=1.2は，DR無効の既存シーンと厳密には同じ物理ではない**．ただし両者ともIK版で全成功した（§2，`tests/object_physics.rs`）．
3. 改善案（未実施）: 立方体geomのcondimを6，転がり摩擦を5e-4にしてジョー接触を元に戻し，テーブル接触は`<pair>`で個別に指定する．既存の学習・評価を完成させることを優先した．

検証（Rust `tests/object_physics.rs` 6件，Python `tests/python/test_object_physics.py` 5件，すべて成功）:
無効時は値が完全に元のまま，再無効化で復元，seed再現性，範囲内，慣性の整合，優先度≥2，不正範囲の拒否，
極端条件（0.001 kg・μ3.0 / 0.2 kg・μ0.05ほか）で静止時ドリフト0.3 mm未満・速度0.01 m/s未満，持ち上げた立方体を離すとテーブルへ落ちて静止すること（z誤差3 mm未満），学習範囲内でIK版全工程成功（3 seed）．

分かったこと:
- **指定範囲（0.02–0.05 kg，μ 0.8–1.5）では，IK GraspとTransport中の保持が270/270成功し，落下は0件だった．** 全工程の失敗は2/270で，いずれもμ0.8でのPlace（離した後の静止位置が許容範囲外）．この範囲ではGraspの成功率を学習で改善する余地がない．IKの性能は意図的に下げていない．
- 範囲外でもμ ≥ 0.2なら0.2 kg（範囲上限の4倍）まで270/270で保持できた．サーボは位置指令−0.17 radで力制限（±2.94 N·m）まで押し付けるため，摩擦で支えられる重さには大きな余裕がある．
- **IKが失敗するのはμ ≤ 0.1のときだけである．** 失敗の主因は持ち上げ開始時に立方体が押し出されること（下記）で，**軽いほど失敗しやすい**（μ0.1でGrasp成功: 0.02 kg 7/30，0.05 kg 17/30，0.1 kg 29/30，0.2 kg 30/30）．重さで滑り落ちているのではない．
- μ ≤ 0.1ではPlace後にテーブル上で滑る失敗も増える．摩擦DRではテーブル接触にも立方体の摩擦が使われる（§1）ためで，Graspでは改善できない．

失敗の診断（0.02 kg，μ0.1，seed 3,000,000，残差0のGoalGraspEnv）: 閉じ終わり（15 step）まで両ジョーで接触しており，持ち上げ開始後の3 step（0.1 s）で立方体が挟持中心から横へ55 mm・上へ20 mm飛び出し，可動ジョーは下限まで閉じた．
ジョー面が平行でないため法線力に押し出し方向の成分が生じ，その比が摩擦係数を上回ると，挟む力を強くしても外れる（くさび効果）と解釈できる．これを裏付ける定数入力の実験（各16〜20 seed）を行った．

- グリッパ指令を接触角付近（0.0〜0.08 rad）に変えて挟む力を弱めても，成功は5〜8/20で変わらなかった（残差0では6/20）．μ1.15では全設定20/20．
- 腕関節に一定の残差（±0.1 rad）を加えると成功は2〜9/16の範囲で変わり，wrist_roll +0.1 radが9/16で最も高かった．

したがって学習の余地は「挟む力の調整」ではなく「手首の姿勢と持ち上げ方」にあり，μ ≤ 0.1では物理的な限界に近い可能性がある．

## 3. Grasp専用環境 `GoalGraspEnv`（第3段階）

`python/robot_sim/grasp_env.py`。Residual RL構成:

- **初期状態**: IK Graspを実行して，Approach / Descendを終えてClose phaseに入った時点（ジョーは開いたまま立方体を囲んでいる）から開始する．
- **行動**: 各stepでIK Graspが指令 a_IK（閉じる，持ち上げる，保持する）を提案し，ポリシーが残差を加える．`a_final = clip(a_IK + [0.06·a₀…a₄ (rad), 0.35·a₅ (rad)], 関節範囲)`．IKは「ポリシー内部のベース制御器」として働き，学習するのは残差だけである．グリッパは位置指令のまま（直接の力指令はない）．残差0ならIK Graspと完全に同じ動作になる（テストで確認）．
- **観測（41次元）**: 関節q・dq（6+6），挟持中心，立方体の位置・四元数・並進/角速度，立方体と挟持中心の相対位置，ジョー/テーブル接触（3），a_IK（6），進捗．**質量・摩擦は含めない．**
- **観測履歴（モデルB）**: `ObservationHistory(K)`で直近K個の（観測，そのとき適用した行動）を現在の観測に連結する（K=4で229次元）．学習とパイプライン推論は同じ`ResidualGrasp`クラスを通るので，履歴・残差・終了の処理が一致する．
- **成功**: Rustの`lifted`（両ジョー・テーブル非接触・30 mm以上）が**連続9 step（0.3 s）**成立すること．一瞬持ち上がっただけでは成功にしない．
- **報酬**（隠れパラメータに依存しない）: 両ジョー接触0.25，挟んだ状態での高さ進捗（30 mmで1），`lifted`で1，滑り（立方体がテーブルを離れた時点からの相対位置変化）×50/m の罰，行動二乗×0.05の罰，成功+10（終了），持ち上げ後の`dropped`で−10（終了）．
- 打ち切り: 75 step，またはIK側のSkillが終了したとき．

### 結果の要約（実測）

- **元の容易な条件（指定範囲）**: IK 149/150，固定補正 150/150に対し，学習モデルは123〜143/150と**全工程成功率が低下した**．GraspとTransportの保持はほぼ150/150のままで，**失敗はPlace（"not resting inside tolerance"）に集中した**．B seed 42だけはTransport中の落下7件，Grasp失敗2件もあった．
- **難条件（学習範囲内のμ ≤ 0.15）**: Grasp成功は IK 174，固定補正 **219**，A 150 / 181，B 160 / 211（/300）．全工程は IK 68，固定補正 **80**，A 62 / 68，B 55 / 73．**最良の学習モデル（B seed 7）でも，Grasp・全工程とも固定補正を下回った．**
- **学習範囲外**（0.2 kg，μ 0.03）: Grasp成功は IK 55，固定補正 64，A 47 / 55，B 44 / 57（/120）．全工程は IK 23，固定補正 23，学習 14〜22．μ=0.03ではどの制御器も全工程0〜1/30．
- 学習モデルの結果はseedによる差が大きい（例: 難条件のGrasp成功が，モデルAで150と181，モデルBで160と211）．履歴あり（B）と履歴なし（A）の差は，seed間の差より小さい．

### Grasp終了時の状態とPlace失敗の原因

μ0.8・0.02 kg・同じ30 seedで，Grasp終了時点を比較した（`python examples/python/analyze_grasp_handoff.py`）:

| | 全工程成功 | Grasp終了時の立方体の傾き | 持ち上げ高さ | グリッパ角 |
|---|---|---|---|---|
| IK | 29/30 | 1.5° | 77.7 mm | 0.092 rad |
| A seed 7 | 23/30 | 3.8° | 44.7 mm | 0.083 rad |
| B seed 42 | 16/30 | 5.0° | 53.4 mm | 0.069 rad |

学習Graspは，成功条件（30 mm・0.3 s）を満たした時点でIKより低い位置で終わり，さらに握り込んで立方体を傾けたまま渡していた．失敗したepisodeでは，離した後に立方体が倒れていた（最終の傾き52〜180°）．
Graspの報酬が後段のPlaceを考慮していないことによる，**Skill間の状態分布の不一致**である．

## 7. 観測された物体の動きへの適応（Model A / B の動作比較）

`examples/python/analyze_grasp_adaptation.py`（seed 3,000,000〜3,000,019．基準は0.035 kg・μ1.15，配置は同じで質量・摩擦だけを変える）．

- **接触前の残差は，全モデル・全条件で完全に一致した．** 行動が分かれるのは最初のジョー接触（step 4〜5）の1 step後（step 5〜6）で，20 episode中15〜20件は接触より後に分かれた．つまり隠れパラメータが漏れているのではなく，**観測した物理的反応（閉じる途中の立方体の動きなど）に応じて残差を変えている．** 摩擦DRではテーブル摩擦もμなので，閉じるときの立方体の滑り方が手がかりになっていると考えられる．
- 接触後の残差の差（基準条件との平均絶対差）は，グリッパで47〜216 mrad，手首で13〜45 mradだった．ただし§2で示したとおり，グリッパの残差はサーボの力制限のためほとんど物理的な効果を持たない．
- **補正の方向は学習seedごとに異なり，一貫した戦略は見られなかった．** 例: 接触後の平均wrist_rollは，μ1.15でA seed 42が−19 mrad，A seed 7が+12 mrad．低摩擦での変化の向きもモデルごとに違った．質量だけを変えた場合（0.1 kg・μ1.15）も13〜33 mradの差が出た．
- 履歴あり（B）の方が反応が大きいという傾向はなかった（B seed 7が最も小さい）．

## 9. 結論：機械学習は何を改善し，何を改善しなかったか

1. **指定範囲（0.02–0.05 kg，μ 0.8–1.5）では，改善の余地がなかった．** IKのGraspと保持は270/270で成功した．SO-101のサーボは力制限まで押し付けるので，質量・摩擦がわからなくても把持できる．
2. **IKが失敗するのはμ ≤ 0.1だけだった．** 主因は，ジョー面が平行でないことによる押し出し（くさび効果）である．挟む力を変えても改善せず，手首の姿勢には効果があった．
3. **SAC残差（A・Bとも）は，IKや固定の手首補正を上回らなかった．** 難条件でのGrasp成功は最良の学習モデルで211/300だったが，学習なしの固定補正（wrist_roll −0.1 rad）は219/300だった．学習で得られた改善の大部分は「手首を一定量ずらす」ことで再現でき，状態に応じた補正による追加の価値は確認できなかった．
4. **学習モデルは，元の容易な条件で全工程の成功率を下げた**（IK 149/150 → 123〜143/150）．原因は，Graspの報酬が後段を考慮せず，立方体を傾けて低い位置で渡したことである（Skill間の状態分布の不一致）．
5. **適応そのものは観測された．** 方策は質量・摩擦を見ずに，接触後の物体の反応に応じて行動を変えていた（接触前は完全に一致し，接触の1 step後に分かれる）．ただし，その変化は主に効果の小さいグリッパ指令に現れ，方向は学習seedごとに異なった．性能の向上には結びつかなかった．観測履歴（B）は，現在の観測のみ（A）に対して明確な利点を示さなかった．
6. 考えられる理由: (a) 失敗の多くは物理的な限界に近い（μ ≤ 0.07ではどの制御器も保持できない）．(b) 残差の上限（±0.06 rad）が，効果のある手首の補正量（約0.1 rad）より小さい．(c) 15万ステップ・選択用30 episodeでは評価のばらつきが大きい．(d) 報酬がGrasp単体で閉じていて，後段に悪影響を与えた．

## 球体（発展課題，独立して記録）

`ObjectShape::Sphere`（`PickPlaceSimulator(shape="sphere")`）は，立方体のgeomを直径25 mmの球に置き換える．質量・摩擦・接触設定は同じで，慣性はコンパイラが 2/5·m·r² で計算する（テストで確認）．

`cargo run --release -p mujoco-runtime --example shape_probe -- sphere 30 3000000`（全IK版，学習なし，seeds 3,000,000〜3,000,029）:

- 球体: **Grasp 30/30，Transport 30/30，Place 0/30**（全件 "not resting inside tolerance"）．
- 同じseedの立方体: 30/30 / 30/30 / 30/30．

SO-101のグリッパは，再学習なしのIKでも球体を把持・運搬できる．失敗はPlaceで，離した後に球が転がり，静止条件（速度 < 0.01 m/s，XY誤差 ≤ 20 mm）を満たさないためである．
これはGraspの適応とは別の問題（配置と転がり）であり，Grasp学習の比較には含めない．対策候補（未実施）: 離す前に下降速度を0にする，離した後に保持して待つ，または静止判定までの待ち時間を延ばす．
